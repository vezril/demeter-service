# 00.5 — Error Model

## Intent

One taxonomy of failure for the whole service, so that a broken decoder, a 503 from Flipp,
and a DB write conflict are distinguishable at the call site and — crucially — so the
orchestrator (08.2) can decide *per error kind* whether to retry, skip a source, or fail
the run. Undocumented upstreams fail in specific, recurring ways; naming those ways is how
we degrade gracefully instead of crashing the daily job.

## Contract

- A single sealed hierarchy `DealWatchError`, with a `retriable: Boolean` and a
  `context: Map[String, String]` on every case (for structured logging, 08.3).
- Errors carry enough to reconstruct what happened **without** re-hitting the network.
- The type is the boundary between "recoverable, degrade this source" and "bug, fail loud".

```scala
sealed trait DealWatchError:
  def retriable: Boolean
  def context: Map[String, String]

object DealWatchError:
  // --- transport (boundary 01/06) ---
  final case class HttpStatus(code: Int, url: String) extends DealWatchError
  final case class Timeout(url: String) extends DealWatchError
  final case class Transport(url: String, cause: String) extends DealWatchError
  final case class BotWall(url: String, signal: String) extends DealWatchError  // 403/Cloudflare/captcha

  // --- decode (01.5) ---
  final case class Decode(source: String, pointer: String, reason: String) extends DealWatchError

  // --- domain (00.x, 02) ---
  final case class InvalidDomain(what: String, reason: String) extends DealWatchError

  // --- persistence (03) ---
  final case class StoreConflict(entity: String, key: String) extends DealWatchError
  final case class StoreUnavailable(cause: String) extends DealWatchError
```

## Retriability, fixed

| Case | retriable | Orchestrator response |
|------|-----------|-----------------------|
| `HttpStatus(5xx)` | yes | backoff + retry, then degrade source |
| `HttpStatus(4xx)` except 429 | no | degrade source, alert operator |
| `HttpStatus(429)` | yes | backoff harder |
| `Timeout` | yes | backoff + retry |
| `Transport` | yes | backoff + retry |
| `BotWall` | no | degrade source immediately, alert operator (this is the "Flipp added auth" signal) |
| `Decode` | no | store raw, skip item/flyer, count toward drift alarm (08.3) |
| `InvalidDomain` | no | skip record, count |
| `StoreConflict` | no | usually benign (idempotent re-run); log at debug |
| `StoreUnavailable` | yes | retry; if persistent, fail the run |

## Notes

- `BotWall` is its own case on purpose. The single most likely way this whole project dies
  is Flipp putting the endpoint behind Cloudflare/auth; giving that its own error type means
  08.2 can react to it distinctly (switch to the Apify fallback source) instead of treating
  it as a generic 4xx.
- `Decode` deliberately does **not** fail the run. A schema drift on three items out of 776
  should degrade quietly and raise a drift metric, not lose you the other 773.
