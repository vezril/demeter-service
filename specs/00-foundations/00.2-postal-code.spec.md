# 00.2 — Postal Code

## Intent

The Flipp endpoints are geographically scoped by Canadian postal code. A `PostalCode`
value type guarantees that whatever we hand to a `FlyerSource` is a syntactically valid
Canadian postal code in the canonical form the endpoints expect, so a typo becomes a
compile-time-adjacent failure at the edge rather than an empty result set three layers in.

## Contract

- Validates the Canadian format `A1A 1A1` (letter-digit-letter, space optional on input,
  digit-letter-digit), case-insensitive on input.
- Excludes the letters Canada Post never uses in postal codes (`D, F, I, O, Q, U`), and
  the two that never appear as the first letter (`W, Z`). This is a real validity check,
  not just a regex on `[A-Z]`.
- Canonicalizes to **upper case, no internal space** (`H2X1Y6`) because that is the form
  the Flipp query string uses. A separate `withSpace` renderer exists for display.
- Exposes the **Forward Sortation Area** (first three chars) because Flipp's response
  distinguishes `flyers` from `outside_fsa_flyers` and 03.4 keys dedup partly on FSA.

## Domain model (sketch)

```scala
final case class PostalCode private (fsa: String, ldu: String):
  def canonical: String = fsa + ldu          // "H2X1Y6"
  def withSpace: String = s"$fsa $ldu"        // "H2X 1Y6"

object PostalCode:
  def parse(s: String): Either[PostalCodeError, PostalCode]

enum PostalCodeError:
  case WrongShape(input: String)
  case IllegalLetter(input: String, letter: Char)
```

## Gherkin

```gherkin
Feature: Canadian postal code

  @pure
  Scenario Outline: Valid postal codes parse and canonicalize
    Given the input "<input>"
    When I parse it as a postal code
    Then it succeeds
    And the canonical form is "<canonical>"
    And the FSA is "<fsa>"

    Examples:
      | input    | canonical | fsa |
      | H2X 1Y6  | H2X1Y6    | H2X |
      | h2x1y6   | H2X1Y6    | H2X |
      | H2X1Y6   | H2X1Y6    | H2X |
      | K1A 0B1  | K1A0B1    | K1A |

  @pure
  Scenario Outline: Structurally invalid inputs are rejected
    Given the input "<input>"
    When I parse it as a postal code
    Then it fails with WrongShape

    Examples:
      | input   |
      | 12345   |
      | H2X     |
      | H2X-1Y6 |
      | HH2 1Y6 |
      | ""      |

  @pure
  Scenario Outline: Letters excluded by Canada Post are rejected
    Given the input "<input>"
    When I parse it as a postal code
    Then it fails with IllegalLetter

    Examples:
      | input   | why                          |
      | D2X 1Y6 | D never used                 |
      | H2I 1Y6 | I never used                 |
      | W2X 1Y6 | W not valid as first letter  |
      | H2X 1O6 | O never used                 |

  @pure
  Scenario: Display form re-inserts the space
    Given a postal code parsed from "H2X1Y6"
    When I render its display form
    Then the result is "H2X 1Y6"
```

## Notes

- Keep the illegal-letter set in one named constant; it's the kind of thing that reads as
  magic and gets mutated in review otherwise.
- Multi-postal support (future) changes nothing here — it just means the orchestrator holds
  a `List[PostalCode]`. Noting it so this stays stable.
