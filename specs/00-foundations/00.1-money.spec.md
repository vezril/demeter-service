# 00.1 — Money

## Intent

A value type for monetary amounts that never loses a cent to floating point. Flyer prices
arrive as `4.99`, `2 for $5`, `$1.50/lb`; every one of them must land in the domain as an
exact integer count of cents in a known currency. All arithmetic the system does on prices
(unit price, discount depth, rolling medians) runs on this type, not on `Double`.

## Why a unit of its own

Every other unit depends on this and none of them should re-derive cent handling. It is
pure, tiny, and a perfect mutation-testing target (off-by-one, rounding-direction, and
sign mutations are exactly the bugs that hurt here).

## Contract

- `Money` wraps a `Long` count of minor units (cents) and a `Currency` (v1: `CAD` only,
  but the currency is explicit so a future USD flyer can't silently mix in).
- Construction from a decimal string or `BigDecimal` is **total or explicitly failed** —
  it returns `Either[MoneyError, Money]`, never throws, never silently truncates.
- Rounding, when a fractional cent is unavoidable (e.g. dividing `$5` across `3` for a
  "3 for $5" unit price), uses **banker's rounding (half-even)** and the rounding is a
  visible, tested decision — see 02.2 which consumes this.
- Formatting is the inverse of parsing for any value that parsed cleanly.

## Domain model (sketch)

```scala
enum Currency { case CAD }

final case class Money private (cents: Long, currency: Currency)

object Money:
  def fromDecimal(s: String, currency: Currency = Currency.CAD): Either[MoneyError, Money]
  def fromBigDecimal(d: BigDecimal, currency: Currency = Currency.CAD): Either[MoneyError, Money]
  def cents(n: Long, currency: Currency = Currency.CAD): Money

enum MoneyError:
  case NotANumber(input: String)
  case TooManyDecimalPlaces(input: String)   // more precision than cents
  case Negative(input: String)               // prices are non-negative in this domain
```

## Notes for the implementer

- The `4,99` case is deliberately a failure *here*. Comma-decimal and `$`/`/lb` stripping
  are the normalizer's job (02.1); `Money` speaks only clean canonical decimals so its
  contract stays trivial and total.
- Keep the constructor private and force construction through the smart constructors so an
  arbitrary `Long` can't fabricate an invalid state elsewhere.
