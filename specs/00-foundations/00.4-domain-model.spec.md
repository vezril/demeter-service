# 00.4 — Core Domain Model

## Intent

The nouns every other context passes around. This spec defines them as immutable data with
explicit optionality, so that "we didn't get a price for this item" is a representable,
non-crashing state rather than a `null` or a `0.0`. The whole system's tolerance for messy
upstream data starts with modelling absence honestly here.

## Types

```scala
final case class MerchantId(value: Int)
final case class FlyerId(value: Long)

final case class Merchant(id: MerchantId, name: String)   // name resolved via 03/01 join

final case class Flyer(
  id: FlyerId,
  merchantId: MerchantId,
  name: String,                    // e.g. "Weekly Flyer", "Quebec"
  validFrom: Instant,
  validTo: Instant,
  postalCode: PostalCode,
  locale: Locale
)

/** One priced (or price-unknown) line item as it appeared in a flyer. */
final case class FlyerItem(
  sourceItemId: String,            // upstream id; NOT stable across weeks
  flyerId: FlyerId,
  merchantId: MerchantId,
  name: BilingualText,
  rawName: String,                 // exact upstream string, preserved verbatim
  currentPrice: Option[Money],     // absent for many big-box items — this is expected
  originalPrice: Option[Money],
  saleStory: Option[String],       // e.g. "2 for $5", "25 points", "50% off"
  validFrom: Instant,
  validTo: Instant
)

/** The normalized, storable fact. Product of 02.6. */
final case class PriceObservation(
  productKey: ProductKey,          // our own stable key (02.7)
  merchantId: MerchantId,
  flyerId: FlyerId,
  observedAt: Instant,
  name: BilingualText,
  effectivePrice: Option[Money],   // best price we could derive (may be a unit price)
  priceBasis: PriceBasis,          // how effectivePrice was derived — provenance matters
  originalPrice: Option[Money],
  saleText: Option[String],
  validFrom: Instant,
  validTo: Instant,
  confidence: Confidence           // how much we trust the parse (02)
)

enum PriceBasis:
  case ScalarPrice          // upstream gave a clean current_price
  case MultiBuyUnit         // derived from "N for $X"
  case PercentOffUnknown    // "% off" but base price unknown -> effectivePrice None
  case ParsedFromText       // pulled a "$X" out of free text
  case Unknown

enum Confidence:
  case High case Medium case Low
```

## Invariants

- `PriceObservation.effectivePrice` is `None` **iff** no price could be responsibly derived.
  A `None` price with `priceBasis = PercentOffUnknown` is a valid, expected record — it
  still tells the watchlist "this item is on some kind of promo".
- `rawName` on `FlyerItem` is never modified. It is the audit trail; 02 reads it, nothing
  overwrites it.
- `validFrom < validTo` for any `Flyer`/`FlyerItem` the system accepts; violations are a
  decode-level rejection (01.5), not a domain object.

## Gherkin

```gherkin
Feature: Domain model invariants

  @pure
  Scenario: An item with no derivable price is representable
    Given a FlyerItem with no current price and saleStory "50% off"
    When it is normalized into a PriceObservation
    Then the effective price is absent
    And the price basis is PercentOffUnknown
    And the observation is still valid and storable

  @pure
  Scenario: Raw upstream name is preserved verbatim through normalization
    Given a FlyerItem whose rawName is "  Natrel 3.25%  |  LAIT 3.25%  "
    When it is normalized
    Then the resulting observation still carries the original rawName unchanged

  @pure
  Scenario Outline: A flyer with a non-positive validity window is not a valid domain object
    Given validFrom "<from>" and validTo "<to>"
    When I attempt to build a Flyer
    Then it is rejected

    Examples:
      | from                 | to                   |
      | 2026-07-30T00:00:00Z | 2026-07-23T00:00:00Z |
      | 2026-07-23T00:00:00Z | 2026-07-23T00:00:00Z |

  @pure
  Scenario: A clean scalar price yields a ScalarPrice basis and high confidence
    Given a FlyerItem with current price 4.99 and no ambiguity
    When it is normalized
    Then the effective price is 4.99
    And the price basis is ScalarPrice
    And the confidence is High
```

## Notes

- `sourceItemId` is explicitly labelled unstable. 02.7 exists precisely because we cannot
  key our history on upstream ids. Keeping the upstream id anyway is useful for debugging a
  single week's fetch.
- `priceBasis` is provenance, and provenance is what lets 07 decide how much a given
  observation should move a rolling median. A `ParsedFromText` price should weigh less than
  a `ScalarPrice` one.
