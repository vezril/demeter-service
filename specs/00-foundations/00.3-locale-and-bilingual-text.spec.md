# 00.3 — Locale & Bilingual Text

## Intent

Quebec flyers come back from Flipp in two shapes depending on the `locale` parameter, and
many items arrive with **both languages jammed into one string**, e.g.
`"LAIT FINEMENT FILTRÉ NATREL | NATREL FINE-FILTERED MILK"`. This unit owns two small
concerns that everything downstream leans on:

1. `Locale` — a closed enum (`fr-ca`, `en-ca`) with the exact query-string rendering the
   endpoints expect.
2. `BilingualText` — a container that can hold a French form, an English form, or both,
   built from the raw single-string field. The *splitting* algorithm lives in 02.5
   (it's normalization); this unit is only the **type** and its accessors, so 00 stays
   dependency-free.

## Why split the type from the splitter

00 must not depend on 02. The domain needs a `BilingualText` type to hold in
`PriceObservation` (00.4); the messy business of deciding where `en` stops and `fr` begins
is normalization and belongs in 02.5. So: dumb container here, smart parser there.

## Domain model (sketch)

```scala
enum Locale(val queryValue: String):
  case FrCa extends Locale("fr-ca")
  case EnCa extends Locale("en-ca")

final case class BilingualText(fr: Option[String], en: Option[String]):
  def primary(preferred: Locale): Option[String]   // preferred, else the other, else None
  def anyForm: Option[String]                        // en, else fr, else None
  def forms: List[String]                            // both, deduped, for matching (04)
```

## Gherkin

```gherkin
Feature: Locale

  @pure
  Scenario Outline: Locale renders to the exact endpoint query value
    Given the locale <locale>
    Then its query value is "<query>"

    Examples:
      | locale | query |
      | FrCa   | fr-ca |
      | EnCa   | en-ca |

Feature: BilingualText container

  @pure
  Scenario: Primary prefers the requested language
    Given a BilingualText with fr "lait" and en "milk"
    When I ask for the primary form preferring FrCa
    Then I get "lait"

  @pure
  Scenario: Primary falls back to the other language when the preferred is absent
    Given a BilingualText with en "milk" and no fr
    When I ask for the primary form preferring FrCa
    Then I get "milk"

  @pure
  Scenario: Primary is None when both are absent
    Given a BilingualText with no fr and no en
    When I ask for the primary form preferring EnCa
    Then I get nothing

  @pure
  Scenario: forms exposes every present language for matching, deduplicated
    Given a BilingualText with fr "lait" and en "milk"
    When I ask for its forms
    Then the forms are exactly ["lait", "milk"]

  @pure
  Scenario: forms deduplicates when both languages carry identical text
    Given a BilingualText with fr "Coca-Cola" and en "Coca-Cola"
    When I ask for its forms
    Then the forms are exactly ["Coca-Cola"]

  @pure
  Scenario: anyForm prefers English then French
    Given a BilingualText with fr "lait" and en "milk"
    When I ask for anyForm
    Then I get "milk"
```

## Notes

- `forms` feeds the matcher (04.3): a watch term should hit whether the flyer named the
  item in French or English. Preserving both, un-mangled, is the whole point.
- Deliberately no locale beyond the two Flipp uses. If a source ever needs `en-us`, add it
  here and the compiler will find every switch that must handle it.
