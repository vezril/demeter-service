# 01.1 — FlyerSource Interface

## Intent

The seam that makes the whole system survivable. Every flyer provider — the Flipp backend
today, an Apify actor as fallback, a captured-fixtures source in tests — implements one
interface. The orchestrator depends on the interface, never on Flipp directly. When Flipp
breaks (and 00.5 `BotWall` says it eventually will), you swap the implementation behind this
seam without touching normalization, storage, watchlist, or alerting.

## Contract

```scala
trait FlyerSource[F[_]]:
  def name: SourceName
  /** Flyers currently active for a postal code. */
  def flyers(postal: PostalCode, locale: Locale): F[Either[DealWatchError, RawFlyerListing]]
  /** All items within one flyer. */
  def items(flyerId: FlyerId, postal: PostalCode, locale: Locale): F[Either[DealWatchError, RawFlyerItems]]
  /** Cross-merchant item search (optional capability; some sources won't have it). */
  def search(term: String, postal: PostalCode, locale: Locale): F[Either[DealWatchError, RawSearchResult]]
```

- Every method returns `F[Either[DealWatchError, A]]` — failure is a value, not an
  exception, so the orchestrator can pattern-match on 00.5 cases.
- The `Raw*` results carry **the archived bytes plus the parsed shape**, not just the parse.
  Decoding is 01.5; this interface hands back both so 03.2 can persist the raw before
  anything trusts the parse.
- `search` is optional capability. A source that can't search returns
  `Left(HttpStatus(404, ...))`-equivalent or a dedicated `Unsupported` — the interface
  documents which methods a source supports via a `capabilities: Set[Capability]`.

```scala
final case class RawResponse(bytes: Array[Byte], contentType: String, fetchedAt: Instant, url: String)
final case class RawFlyerListing(raw: RawResponse, flyers: List[Flyer])
final case class RawFlyerItems(raw: RawResponse, items: List[FlyerItem])
final case class RawSearchResult(raw: RawResponse, flyerItems: List[FlyerItem], ecomItems: List[FlyerItem])
```

## Gherkin

```gherkin
Feature: FlyerSource is a swappable seam returning raw + parsed

  @boundary
  Scenario: A source hands back the raw bytes alongside the parsed flyers
    Given a FlyerSource backed by a captured flyers response
    When I request flyers for a postal code
    Then I receive the parsed flyers
    And I receive the original raw bytes and the URL they came from

  @pure
  Scenario: Failures surface as typed values, not thrown exceptions
    Given a FlyerSource whose transport returns a 503
    When I request flyers
    Then the result is a Left containing an HttpStatus error with code 503
    And no exception escapes

  @pure
  Scenario Outline: A source advertises its capabilities honestly
    Given the <source> source
    Then its capabilities include <caps>

    Examples:
      | source        | caps                         |
      | Flipp         | flyers, items, search        |
      | ApifyFallback | flyers, search               |
      | Fixture       | flyers, items, search        |

  @pure
  Scenario: Calling an unsupported capability fails cleanly
    Given a source whose capabilities do not include search
    When I call search on it
    Then it returns a Left indicating the capability is unsupported
    And it does not perform any network call
```

## Notes

- The `F[_]` is your effect type (cats-effect `IO` in practice). Specs stay effect-agnostic;
  tests can instantiate with a synchronous fixture effect.
- Keeping `search` optional matters for 06: the enrichment sources implement a *different*
  interface (06.1), but a couple could in principle also satisfy `FlyerSource`. Don't force
  a fit — separate interfaces, one adapter each.
