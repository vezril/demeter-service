# 08.2 — Source Degradation

## Intent

Keep the service useful when a source breaks. Undocumented endpoints fail; the question is
whether the run degrades gracefully or dies. This unit owns the policy that turns 00.5 error
kinds into source-level decisions: retry, switch to a fallback source, or run partially. The
single most important case is `BotWall` on Flipp — the "they added auth" event — which must
trigger a switch to the Apify fallback (or a clean partial run) plus an operator alert, not a
crash.

## Policy (pinned)

- **Flipp `BotWall`** → mark Flipp degraded for the run, attempt the configured fallback
  `FlyerSource` (Apify actor) if enabled; regardless, emit an operator-attention alert. Never
  retry a bot wall in a tight loop.
- **Flipp repeated 5xx/timeout** past the 01.6 retry budget → degrade Flipp for the run,
  emit operator alert, continue with whatever was already fetched.
- **An enrichment source down** (06) → drop enrichment for the run; history-only verdicts.
  Never blocks alerts.
- **Store unavailable** (00.5 `StoreUnavailable`, retriable) → retry per policy; if still
  down, fail the run loudly (this one *should* stop — you can't trust a run that can't
  persist).
- Degradations are recorded in the `RunReport` and surface in 08.3.
