# 04.3 — Matcher

## Intent

Decide whether a `PriceObservation` matches a `WatchItem`. This is the core discovery step:
it must catch the item whether the flyer named it in French or English, tolerate word-order
and minor spelling differences, and reject near-misses that would produce false alerts.
Pure function over normalized text (04.2), matching against every language form (00.3
`forms`).

## Matching strategy (layered)

1. **Merchant scope** (04.1) — if out of scope, no match, short-circuit.
2. **Token containment** — a term matches if all its normalized tokens appear in some
   normalized form of the item name. ("milk" ⊆ "natrel fine filtered milk" → hit.)
3. **Fuzzy fallback** — if no exact containment, a term matches when its normalized string is
   within a bounded edit distance (Jaro-Winkler ≥ threshold, or Levenshtein ≤ k) of a
   contiguous window of the item name. This catches "yogourt"/"yoghurt" style variance.
4. A `WatchItem` matches if **any** of its terms matches (terms are OR'd).

Each match carries a `MatchScore` (04.4) so 05.2 can rank/dedupe.
