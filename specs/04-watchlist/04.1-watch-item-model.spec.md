# 04.1 — Watch Item Model

## Intent

Define what a user watch entry *is*: the thing you're looking for, the conditions under
which it counts as a hit, and the bilingual/synonym terms it should match on. Kept as a pure
data model with validation, so the matcher (04.3) and the deal decision (05.1) have a stable
contract to consume.

## Model

```scala
final case class WatchItem(
  id: WatchId,
  label: String,                    // human name, e.g. "Milk 4L"
  terms: NonEmptyList[String],      // match terms, any language: ["milk","lait"]
  excludeTerms: List[String],       // terms that VETO a match (see below)
  merchants: Set[MerchantId],       // empty = any merchant
  maxPrice: Option[Money],          // alert only at/below this
  requireSale: Boolean,             // only alert when it looks like a genuine sale (07)
  minDiscountPct: Option[Percent],  // optional floor on discount depth
  active: Boolean
)
```

- **`excludeTerms` veto a match however well a term scored** (added 2026-08-24). A watch
  for `butter` alerted on peanut butter, butter croissants, Butter Chicken, lip butter and
  shea-butter deodorant. Of 33 real alerts surviving a $6 ceiling, only 8 were dairy
  butter — and no price ceiling separates them, because peanut butter at $2.28 is *cheaper*
  than butter. Adding exclusions took one real run from 28 alerts to 9, of which 6 are
  dairy butter.

  Exclusions are matched by the **same rules as terms**, so `arachide` also catches
  `arachides` without a second entry. That consistency is deliberate — someone writing an
  exclusion expects it to behave like a term — and it means the fuzzy length floor (04.3)
  applies to them too.

  A term that is also excluded is **rejected at construction** (`TermAlsoExcluded`): such a
  watch can never match anything, and accepting it silently yields something that looks
  configured and is permanently inert. Compared after normalization, so case and accents
  cannot slip past.

- At least one term (`NonEmptyList`). Terms are stored raw; normalization for matching is
  04.2's job at match time, so a user can type "café" or "Coca-Cola" naturally.
- `merchants` empty means "any" — the common case. A watch scoped to specific merchants
  matches only those.
- The alerting conditions (`maxPrice`, `requireSale`, `minDiscountPct`) are captured here but
  *evaluated* in 05.1 — this unit only holds and validates them.
