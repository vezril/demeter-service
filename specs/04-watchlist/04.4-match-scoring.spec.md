# 04.4 — Match Scoring

## Intent

Attach a quality score to each match so that when several observations match one watch item
(common — many flyers carry milk), alerting can pick the best and suppress the noise. Pure
function; no side effects. Score combines match tightness, observation confidence (02.6),
and price attractiveness.

## Score model

```scala
final case class MatchScore(
  textScore: Double,        // 0..1, how tightly the term matched (exact > fuzzy)
  confidence: Confidence,   // carried from the observation
  priceRank: Double         // 0..1, cheaper (or deeper discount) ranks higher
):
  def combined: Double      // weighted; documented, tested weighting
```

- `textScore`: exact token containment scores 1.0; fuzzy scores by its similarity ratio.
- `priceRank`: within a match group, the cheapest effective price ranks highest; observations
  with no price rank lowest (they can't be compared on price).
- `combined` is a documented weighting (default: text 0.4, confidence 0.3, price 0.3). The
  weights are config, not magic constants.

## Gherkin

```gherkin
Feature: Score and rank matches

  @pure
  Scenario: An exact token match scores higher than a fuzzy one
    Given an exact-containment match and a fuzzy match for the same term
    When I score both
    Then the exact match has a higher text score

  @pure
  Scenario: A high-confidence scalar-priced observation outranks a low-confidence parsed one
    Given two matches with equal text scores
    And one has High confidence and one has Low
    When I score both
    Then the High-confidence match ranks higher

  @pure
  Scenario: Within a group the cheapest priced match ranks first on price
    Given three matches priced 2.50, 2.99, and unknown
    When I rank them by price
    Then 2.50 ranks first
    And the unknown-price match ranks last

  @pure @property
  Scenario: Combined score stays within 0..1
    Given any component scores in range
    When I compute the combined score
    Then it is between 0 and 1
