# 03.4 — Flyer Dedup Ledger

## Intent

Decide, each day, which flyers are *new or changed* and therefore worth fetching in full
(the expensive per-flyer items call, 01.4). Flyers run weekly; re-pulling all 121 every day
is wasteful and raises your request profile. This ledger tracks which flyer ids we've
already fully ingested and within which validity window, so the daily run does ~15 heavy
fetches a week instead of ~120.

## Contract

```scala
trait FlyerLedger[F[_]]:
  /** Given today's listing, return the flyers that need a full item fetch. */
  def selectToFetch(listing: List[Flyer], now: Instant): F[List[Flyer]]
  def markFetched(flyerId: FlyerId, window: (Instant, Instant), rawId: RawResponseId): F[Unit]

```

Selection rule (pinned):
- A flyer needs fetching if **either** its id has never been marked fetched, **or** its
  `valid_from`/`valid_to` window differs from what we recorded (a re-issued flyer under the
  same id), **or** the recorded fetch is older than a configured max age (default: refetch
  once per validity window).
- A flyer already fetched for its current window is skipped.
- `first_seen_at` / `last_seen_at` on the `flyer` row (03.1) are updated regardless, so we
  can see a flyer's lifespan even when we skip re-fetching it.

## Gherkin

```gherkin
Feature: Fetch only new or changed flyers

  @boundary
  Scenario: A never-seen flyer is selected for fetching
    Given a listing containing flyer 900 which the ledger has never recorded
    When I select flyers to fetch
    Then flyer 900 is selected

  @boundary
  Scenario: A flyer already fetched for its current window is skipped
    Given flyer 900 was fetched for window [Jul23, Jul30]
    And today's listing shows flyer 900 with the same window
    When I select flyers to fetch
    Then flyer 900 is not selected

  @boundary
  Scenario: A re-issued flyer with a changed window is re-selected
    Given flyer 900 was fetched for window [Jul16, Jul23]
    And today's listing shows flyer 900 with window [Jul23, Jul30]
    When I select flyers to fetch
    Then flyer 900 is selected

  @boundary
  Scenario: Seen timestamps update even when a flyer is skipped
    Given flyer 900 is skipped for re-fetching
    When selection runs
    Then flyer 900's last_seen_at is advanced to now

  @boundary
  Scenario Outline: A stale fetch beyond max age is refreshed
    Given flyer 900 was last fetched <age> ago with max age 7 days
    When I select flyers to fetch
    Then flyer 900 is <selected>

    Examples:
      | age     | selected     |
      | 2 days  | not selected |
      | 8 days  | selected     |
