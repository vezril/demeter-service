# 05.3 — Alert Model & Rendering

## Intent

Define the `Alert` payload and render it to human-readable text for each sink. Pure: takes a
`Deal` + context, produces a structured `Alert` and its rendered forms. Rendering is
separated from delivery (05.4/05.5) so message wording is testable without touching a
network, and so the same alert can render differently for Home Assistant vs a phone push.

## Model

```scala
final case class Alert(
  watchLabel: String,
  merchantName: String,
  itemName: String,           // preferred-locale primary form
  price: Option[Money],
  saleText: Option[String],
  verdict: DealVerdict,        // "cheapest in 8 weeks", etc. (07.3)
  validTo: Instant,
  score: Double
):
  def renderPlain(locale: Locale): String
  def renderStructured: Json   // for the HA sink (05.4)
```

- The plain render is one line, locale-aware, price-first when a price exists, and includes
  the verdict phrase from 07.3 ("cheapest in 8 weeks") because that's the part that makes an
  alert *actionable* rather than just informational.
- A no-price promo renders the sale text instead of a price ("50% off — ends Wed").

```gherkin

  @pure
  Scenario: A priced deal renders price, merchant, and verdict
    Given an alert for "Milk 4L" at Metro, 2.50, verdict "cheapest in 8 weeks", ends Jul30
    When I render it plain in English
    Then the text contains "2.50", "Metro", and "cheapest in 8 weeks"

  @pure
  Scenario: A no-price promo renders the sale text
    Given an alert with no price and sale text "50% off"

    Then the text contains "50% off"
    And it does not contain a fabricated price

  @pure
  Scenario: French locale renders in French
    Given an alert and locale fr-ca
    When I render it plain
    Then the price and date are formatted for French Canadian conventions

  @pure
  Scenario: The structured render carries machine-readable fields for Home Assistant
    Given any alert
    When I render it structured
    Then the JSON includes item, merchant, price cents, verdict, and valid-to
