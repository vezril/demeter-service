# 05.2 — Alert Dedup

## Intent

Stop the same deal alerting every single day for the week the flyer is valid. A flyer runs
7 days; without dedup you'd get 7 identical "milk $2.50 at Metro" notifications. This unit
decides whether an alert-worthy deal is *new* relative to what's already been sent. Pure
decision against a record of prior alerts (the state is passed in; persistence is 05.4's
concern).

## Dedup key and rule

```scala
final case class AlertKey(watchId: WatchId, productKey: ProductKey, flyerWindow: (Instant, Instant))
def isNew(candidate: Deal, alreadyAlerted: Set[AlertKey]): Boolean
```

- Dedup key = watch + product + the flyer's validity window. The *same* deal within the same
  window is suppressed after the first send.
- A **price drop** within the window is a new alert: if the effective price falls below the
  previously alerted price for the same key, re-alert (the deal got better).
- A new flyer window for the same product is a new alert (next week's sale is news again).

## Gherkin

```gherkin
Feature: Suppress repeat alerts, surface genuinely new ones

  @pure
  Scenario: The same deal in the same window alerts only once
    Given a deal already alerted for (watch W, product P, window [Jul23,Jul30])
    When the same deal appears again in the same window
    Then it is not re-alerted

  @pure
  Scenario: The same product in a new flyer window alerts again
    Given a deal alerted for window [Jul16,Jul23]
    When the product is on sale again in window [Jul23,Jul30]
    Then it is alerted

  @pure
  Scenario: A price drop within the same window re-alerts
    Given a deal alerted at 2.99 for a window
    When the same product drops to 2.50 within that window
    Then it is re-alerted as an improved deal

  @pure
  Scenario: A price rise within the window does not re-alert
    Given a deal alerted at 2.50 for a window
    When the same product shows 2.99 within that window
    Then it is not re-alerted
