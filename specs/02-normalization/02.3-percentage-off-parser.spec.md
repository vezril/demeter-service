# 02.3 — Percentage-Off Parser

## Intent

Interpret `"50% off"`, `"Save 25%"`, `"jusqu'à 40% de rabais"`, `"1/2 price"`, and the
free-item promos (`"gratuit"`, `"free"`) that big-box flyers use instead of prices. When a
base (regular) price is known, compute the sale price; when it isn't — the common Canadian
Tire case — record the discount rate with `PriceBasis.PercentOffUnknown` so the item is
still a flaggable promo even without a dollar figure.

## What it handles

- `N% off`, `save N%`, `N% de rabais`, `rabais de N%`.
- Ranges: `"up to 40% off"` / `"jusqu'à 40%"` → capture as an *upper-bound* discount (marked
  as such; a 40%-max sale is weaker than a flat 40%).
- `"1/2 price"`, `"half price"`, `"moitié prix"` → 50%.
- Free-item language: `"gratuit"`, `"free"` when standalone → 100% off (with care: "buy 2 get
  1 free" is 02.2's job, not this — this handles only a bare free-item claim).

## Contract

```scala
final case class PercentOff(
  rate: Percent,               // 0..100
  isUpperBound: Boolean,       // "up to"
  salePrice: Option[Money]     // computed iff a base price was supplied
)

def parsePercentOff(text: String, basePrice: Option[Money], locale: Locale): Option[PercentOff]
```

```gherkin

      | Save 25%                | EnCa   | 25   | false |
      | 40% de rabais           | FrCa   | 40   | false |

  @pure
  Scenario: A bare "free" claim is treated as 100% off, but a BOGO is not
```

## Notes

- The `"25 points"` case returning nothing matters: Metro/loyalty flyers use "N points" as
  the offer, which is neither a price nor a percentage. It should fall through cleanly to be
  recorded as an opaque `saleText` by 02.6, not misread as a discount.
- `isUpperBound` feeds 07: an "up to 40%" promo must not be scored as a guaranteed 40%
  markdown. Cheap field, prevents an over-eager alert.
