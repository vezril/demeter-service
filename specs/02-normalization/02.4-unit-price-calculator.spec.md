# 02.4 — Unit Price Calculator

## Intent

Normalize prices to a comparable basis. `$4.99` for 4L of milk and `$2.99` for 1L are not
comparable until both are expressed per litre. This unit extracts a size/quantity from the
item name (`"4 L"`, `"500g"`, `"12 x 355 mL"`, `"paquet de 6"`) and, given a price, computes
a price-per-standard-unit. It's what lets 07 answer "is this actually cheap" across pack
sizes, and it's the piece that makes cross-merchant comparison meaningful.

## What it handles

- Size extraction from names: `4 L`, `500 g`, `1.5kg`, `355 mL`, `12 x 355 mL` (multipack →
  total volume), `750ml`, `paquet de 6` / `pack of 6`.
- Standard-unit normalization: volumes → per litre; weights → per kg; countables → per item.
- Multipack math: `12 x 355 mL` = 4.26 L total.
- Returns `None` when no size is parseable (common; not an error).

## Contract

```scala
enum StdUnit { case PerLitre, case PerKg, case PerItem }
final case class Size(quantity: BigDecimal, unit: StdUnit, packCount: Int)
final case class UnitPrice(price: Money, per: StdUnit)

def parseSize(name: String, locale: Locale): Option[Size]
def unitPrice(price: Money, size: Size): UnitPrice
```

- `parseSize` and `unitPrice` are separate so size extraction can be tested without prices
  and reused by 07 for matching sizes across weeks.

## Notes

- Rounding on unit price uses 00.1 half-even. The `$4.99/4L → 125` and `12x355mL → 4.26L`
  cases are the ones to pin against mutation.
- Ambiguity is real: `"500 g"` in a name could be net weight or a serving size. v1 takes the
  first parseable size token and marks lower confidence when the name has multiple size-like
  tokens — 02.6 folds that into `Confidence`. Don't over-engineer; flag and move on.
- French unit words (`paquet de`, `boîte de`, `chacun`) need their own token list, kept
  beside the English one.
