# 02.6 — Observation Assembler

## Intent

The orchestrating pure function of the normalization context: take one `FlyerItem` (raw,
messy, from 01.4) and produce one `PriceObservation` (clean, storable, from 00.4) by
composing the smaller parsers (02.1–02.5, 02.7). This is where the **precedence rules** live
— when an item has both a scalar `current_price` *and* a `sale_story` of `"2 for $5"`, which
wins? — and where `PriceBasis` and `Confidence` get assigned. No IO; the whole thing is a
deterministic function of its input, which is what makes the messy real-world data
tractable and testable.

## Precedence (the core decision, pinned)

Given a `FlyerItem`, derive `effectivePrice` and `priceBasis` in this order:

1. **Scalar** — if `current_price` is present, that is the effective price;
   `basis = ScalarPrice`, `confidence = High`. (A `sale_story` may still be *recorded* as
   `saleText`, but it does not override a concrete price.)
2. **Multi-buy** — else if `sale_story`/`pre`/`post` text parses as a multibuy (02.2) with a
   derivable unit price, use that unit price; `basis = MultiBuyUnit`, `confidence = Medium`.
3. **Percent-off with base** — else if percent-off (02.3) parses *and* an `original_price`
   is present, compute sale price; `basis = ParsedFromText`, `confidence = Medium`.
4. **Percent-off without base** — else if percent-off parses but no base price:
   `effectivePrice = None`, `basis = PercentOffUnknown`, record the rate in `saleText`.
5. **Price in free text** — else if a bare price token (02.1) is findable in `name`:
   `basis = ParsedFromText`, `confidence = Low`.
6. **None of the above** — `effectivePrice = None`, `basis = Unknown`; still a valid
   observation carrying whatever `saleText` we have (e.g. `"25 points"`).

At every step, if 02.4 can extract a size, attach a unit price. Bilingual name via 02.5.
Product key via 02.7. Confidence is the **minimum** of the price-derivation confidence and
the name-split confidence.

## Gherkin

```gherkin

  Scenario: A scalar price wins over a coexisting sale story

    Then the effective price is 4.99

  Scenario: A multibuy with no scalar price yields a derived unit price
    Given a FlyerItem with no current_price and sale_story "2 for $5"
    When I assemble the observation

    And the price basis is MultiBuyUnit

  @pure

    And the price basis is ParsedFromText

  Scenario: A parseable size attaches a unit price regardless of basis
```

## Notes

- This is the single most important unit to mutation-test, because the precedence ladder is
  pure branching logic and a flipped condition silently corrupts every downstream stat.
  Aim high on the mutation gate here specifically.
- The precedence is a *policy*, and policies change. Keep the ladder as data/config where
  reasonable (an ordered list of `PriceStrategy` attempted in turn) so re-ordering is a
  one-line change with an obvious test diff, not a rewrite.
- Note the deliberate asymmetry: a scalar price is `High`, everything derived is at best
  `Medium`, free-text is `Low`. 07 uses this to weight history — see 07.2.
