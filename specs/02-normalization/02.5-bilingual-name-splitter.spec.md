# 02.5 — Bilingual Name Splitter

## Intent

Split Flipp's jammed-together bilingual item names into a `BilingualText` (00.3). Quebec
flyers routinely return `"LAIT FINEMENT FILTRÉ NATREL | NATREL FINE-FILTERED MILK"` or the
same idea with other separators. Getting both language forms out cleanly is what lets the
watchlist match a French *or* English watch term against the same item (04.3). Pure,
heuristic, and honest about its own uncertainty.

## What it handles

- Explicit separators: `|`, ` / ` (spaced slash), ` - ` in the bilingual position, newline.
  The pipe is the common one in observed data.
- Which side is which language: detect via diacritics and language-specific tokens (French:
  `é à ç ù`, `lait`, `de`, `avec`; English: `milk`, `with`, `the`). The split produces
  `fr`/`en` assignments, not just `left`/`right`.
- No separator: a single-language name → put it in the detected language, leave the other
  `None`. Never fabricate a translation.
- Ambiguous / can't tell: put the whole string in *both* `forms` (so matching still works)
  but mark low confidence.

## Contract

```scala
final case class SplitResult(text: BilingualText, confidence: Confidence)

def splitBilingual(raw: String): SplitResult
```

- The **input `rawName` is never mutated** (00.4). This produces a new `BilingualText`; the
  raw survives untouched.

## Gherkin

```gherkin
Feature: Split bilingual flyer names

  @pure
  Scenario: A pipe-separated bilingual name splits by detected language
    Given the raw name "LAIT FINEMENT FILTRÉ NATREL | NATREL FINE-FILTERED MILK"
    When I split it
    Then the French form is "LAIT FINEMENT FILTRÉ NATREL"
    And the English form is "NATREL FINE-FILTERED MILK"
    And the confidence is High

  @pure
  Scenario Outline: Various separators are recognized
    Given the raw name "<raw>"
    When I split it
    Then the French form is "<fr>"
    And the English form is "<en>"

    Examples:
      | raw                        | fr        | en        |
      | Lait / Milk                | Lait      | Milk      |
      | Fromage - Cheese           | Fromage   | Cheese    |
      | Beurre \| Butter           | Beurre    | Butter    |

  @pure
  Scenario: A single-language name goes in the detected language only
    Given the raw name "MASTERCRAFT 5-Shelf Resin Rack"
    When I split it
    Then the English form is "MASTERCRAFT 5-Shelf Resin Rack"
    And the French form is absent
    And the confidence is High

  @pure
  Scenario: A French-only name is detected as French
    Given the raw name "Beurre d'arachide croquant"
    When I split it
    Then the French form is "Beurre d'arachide croquant"
    And the English form is absent

  @pure
  Scenario: An ambiguous name is placed in both forms with low confidence
    Given the raw name "Cola 2L"
    When I split it
    Then both forms contain "Cola 2L"
    And the confidence is Low

  @pure
  Scenario: The raw name is never altered by splitting
    Given a raw name with leading and trailing spaces
    When I split it
    Then the original raw name string is returned unchanged elsewhere in the pipeline
```

## Notes

- Language detection here is deliberately cheap (diacritic + stopword heuristic), not a real
  language model. It only needs to be right often enough that watch-term matching works;
  when unsure it degrades to "both forms" which is safe for matching, just noisier.
- Brand names (`Coca-Cola`, `MASTERCRAFT`) are language-neutral and will often land as
  "ambiguous → both forms". That's fine — it's the correct behaviour for matching.
- A pipe with three segments (rare, seen occasionally) → take the outer two as the language
  pair and fold the middle into low confidence. Cover it once; don't chase every oddity.
